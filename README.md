# Kadai Khata (கடை खाता / கடை கணக்கு)

A Tanglish (Tamil + English) voice/text udhaar (credit) ledger assistant designed for small neighborhood shop owners (kirana / petty shops) in Tamil Nadu.

Shop owners speak or type natural everyday phrases like *"Ravi-ku 500 rupees udhaar kuduthen"* (Gave 500 rupees credit to Ravi) or *"Priya 200 kuduthanga"* (Priya paid 200). A Meta AI model parses the intent into a structured transaction draft via tool calling. The shop owner verifies and confirms the transaction before anything is saved to the ledger.

---

## What It Does
- **Tanglish Speech & Text Understanding**: Parses conversational Tamil-English statements for credit given (*udhaar*) and repayments (*panam vanthathu*).
- **Human-in-the-Loop Confirmation**: AI never writes directly to the database without explicit owner review and approval.
- **Ledger & Outstanding Tracking**: Real-time balance calculations per customer with transaction history.
- **Polite Payment Reminders**: Drafts gentle, localized reminder messages in Tanglish/Tamil for WhatsApp or SMS.
- **Mobile-First Interface**: Designed for single-hand mobile use by shopkeepers with quick actions.

## Quick Setup

### Prerequisites
- Python 3.11+ (tested on Python 3.14)
- Git

### Installation (PowerShell on Windows)
```powershell
# 1. Clone repository
git clone https://github.com/silambarasan-sh/kadai-khata.git
cd kadai-khata

# 2. Create and activate virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3. Install dependencies
pip install -r requirements.txt

# 4. Setup environment variables
Copy-Item .env.example .env

# 5. Run database migrations
python manage.py migrate

# 6. Seed demo data (8 Tamil Nadu customers with 40 realistic transactions)
python manage.py seed_demo_data

# 7. Check Meta AI model connectivity (in mock or live mode)
python manage.py meta_check

# 8. Run test suite
pytest

# 9. Start development server
python manage.py runserver
```

## What Was Built During the Hackathon
- **Django Ledger Backend**: Clean models for `Customer` and `LedgerEntry` with decimal precision for currency.
- **Core Ledger Services**: Balance computation, customer resolution, amount bounds validation, and idempotent seeding.
- **Meta AI Client Layer (`ledger/meta_client.py`)**:
  - The single centralized entry point for calling Meta models via the OpenAI Python SDK.
  - Exponential backoff with jitter on HTTP 429 (rate limits) and 5xx (server errors).
  - Explicit non-retry on HTTP 400 (bad requests).
  - Clear error reporting for HTTP 401 (invalid/missing key) and 404 (model/endpoint not found).
  - Fully deterministic offline mock client for zero-cost testing and continuous integration.
- **Management Commands**:
  - `seed_demo_data`: Seeds 8 Tamil Nadu customers and 40 realistic transactions over 60 days (idempotent).
  - `meta_check`: Diagnostic utility to verify Meta API connection, model ping, token counts, and latency without leaking secrets.
- **Test Suite**: Comprehensive pytest suite covering models, service logic, bounds validation, idempotency, and Meta client behaviors (mock, live, 401, 400, 429 backoff).

## Meta Models Used & How the AI is Used

### Model & Specifications
- **Model**: `muse-spark-1.3` (Standard mode)
- **Base Endpoint**: `https://api.meta.ai/v1`
- **SDK**: OpenAI Python SDK (`openai.OpenAI`)
- **Key Authentication**: Handled via `MODEL_API_KEY`. The real key format is `LLM|numeric_id|secret`; it contains `|` characters, so it must be wrapped in double quotes in `.env`.
- **Interface**: Chat Completions API with Function Tools (`record_ledger_entry`, `ask_clarification`).

### Verified API Findings (Live Probe)
1. **Tool Choice**: Meta Model API strictly supports `tool_choice="auto"` (sending `"required"` returns HTTP 400).
2. **Parallel Tool Calling**: Verified working live — compound sentences (e.g. *"Ravi-ku 500 udhaar kuduthen, Mani 200 thirumba kuduthaan"*) return multiple tool calls simultaneously in a single turn.
3. **Reasoning Effort**: `reasoning_effort` (`minimal`, `low`) is supported and configurable via `META_REASONING_EFFORT`.

### Human-in-the-Loop Confirmation Architecture
1. **Prompt Context**: Injects existing shop customer names into the system prompt to guide spelling consistency.
2. **Draft Isolation**: The AI has **no save permissions**. Every tool call only populates a `DraftEntry` model in the database with status `pending`.
3. **Explicit Confirmation**: The shopkeeper inspects the proposed draft (with exact match or fuzzy match suggestion), makes optional edits, and explicitly confirms or rejects it.
4. **Honest Labeling**: Every draft carries an immutable `source_label`:
   - `live`: Derived directly from live Meta Model API tool calls.
   - `mock`: Generated by the deterministic local mock parser.
   - `fallback`: Generated by the local rule-based regex parser if Meta API encounters errors or returns no tool calls.

### Evaluation & Benchmarks (`eval_parser`)

We test parser accuracy against two separate test suites:
1. **Golden Dataset (`tests/golden_sentences.json`)**: 20 open-book sentences designed alongside prompt rules (compound transactions, Tamil number words, prompt injections, and conversational chatter).
2. **Held-Out Dataset (`tests/heldout_sentences.json`)**: 14 unseen, frozen sentences never tuned against prompt rules (including colloquial Tamil phrasing, future promises, 5 lakh limits, and questions). **The held-out set represents our fair, unbiased generalization metric.**

### Safety Warnings Layer
`DraftEntry` instances automatically generate safety warnings displayed in the UI / API responses:
1. **New Customer on Payment**: Flags when a repayment is recorded for someone with no prior credit history.
2. **Overpayment Warning**: Alerts if a payment exceeds the customer's current outstanding balance (would cause negative balance).
3. **Anomalous Amount**: Flags amounts that exceed 3x average and 2x previous maximum for that customer.
4. **Ambiguous Fuzzy Match Guard**: If more than one customer matches a name, the draft refuses auto-selection, exposes `candidates`, and blocks confirmation until the shopkeeper explicitly selects the intended customer.
