⚙ How Kadai Khata Works

Technical Judge Reference — Live AI vs Code-Enforced Safety

🤖 Live Meta AI Features Used

1. Single-Turn Tool Calling:

Translates colloquial Tanglish speech/text into typed record_ledger_entry or ask_clarification tool calls.

2. Parallel Tool Calls:

Extracts multiple customer transactions simultaneously from compound sentences (e.g., credit given plus payment received in one utterance).

3. Multimodal Vision:

Scans handwritten Tamil physical notebook pages directly into structured draft rows in-memory. Zero image bytes stored on disk or DB.

4. Autonomous Agent Loop:

Daily Collections Agent runs an autonomous multi-turn ReAct reasoning loop calling read-only ledger tools to review debt aging, payment habits, and propose polite collection actions.

5. Audio Voice Transcription (Muse Voice Transcribe):

Converts shopkeeper spoken Tamil and Tanglish voice notes into editable text via muse-voice-transcribe-1.0 with vocabulary biasing (existing customer names) and languageBias: ["Tamil"]. Parsing is subsequently performed by muse-spark-1.3 only after the owner reviews the transcript. Zero audio bytes stored on disk or DB.

⚙ Inference Engine Selection

1. Meta Model API (Default Engine):

Direct API using muse-spark-1.3 for Tanglish text parsing, Ask balance queries, and reminder drafting. Notebook photo vision, muse-voice-transcribe-1.0 speech recognition, and the autonomous collections agent run exclusively on Meta Model API.

2. Baseten · Muse Spark Open (Partner Engine):

Meta's open-weight meta-models/muse-spark-open-1026 hosted on Baseten's serverless inference infrastructure. Used for Tanglish text parsing, Ask balance queries, and reminder drafting. Retains identical tool-calling schemas and safety verification. Both engines share the same rate limits and daily live-call budget.

🔒 What is NOT AI (Strict Code Boundaries)

1. Balances & Arithmetic:

Customer balances, aging buckets (0-30, 31-60, 60+), and running totals are computed 100% deterministically in Python/SQL. The LLM is never permitted to calculate balances.

2. Balance Verifier:

All reminder messages and ask answers are strictly verified against ground-truth database balances before display. Any hallucinated numbers immediately trigger fallback to verified deterministic templates.

3. SHA-256 Cryptographic Hash Chain:

Every single agent execution step, tool input, tool output, and final plan is cryptographically linked with previous-step SHA-256 hashes, producing an immutable, tamper-evident audit trail replayable offline.

4. Owner Transcript Review Screen:

Voice audio is never directly booked into the ledger. The shopkeeper reviews and edits the transcribed text before pressing Send, preventing transcription ambiguities from affecting accounts.
